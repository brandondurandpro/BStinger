# The shards of the big UI modules: a step of `run-tests --only` that is `<module>.<shard>` runs only the test classes
# of the shard (`./kotlin test -m <module> --include-classes=...`), so that the CI runs a module in several jobs.
#
#   module  shard  class pattern  seconds on Windows  seconds on Linux
#
# - A line puts the classes matching its pattern (fully qualified name, `*` and `?` as wildcards) in a shard of the module.
# - The shard `rest` has no line: it runs every class of the module that is in no other shard (`--exclude-classes`
#   for each pattern below), so a test class added later runs without anyone editing this file.
# - A module without line has no shard: its step is the whole module. tools/ci/check-test-groups, which the CI runs, fails
#   when a pattern matches no class or a class of two shards, and when a group of tools/ci/*-test-groups.txt does not
#   run every module (or every shard of a module) exactly once. `./run-tests --list <step>` prints the arguments of a step.
# - The seconds are the time of each class in the CI run 43650560775 (Nov 2026), from the timestamps of its log. They only
#   balance the shards (and the groups): nothing reads them. A shard is about 2 minutes of tests; add a class to the
#   lightest shard when you rebalance, or leave it to `rest`.
